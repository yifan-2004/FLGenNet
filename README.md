# FLGenNet

**A lightweight low-light image enhancement network based on frequency decomposition.** FLGenNet separates low- and high-frequency components with a Laplacian pyramid, enhances luminance and color at low resolution, and guides the reconstruction of fine details.

[Paper / SSRN](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6482333) · [Original repository](https://github.com/OuyangYifan0324/FLGen-Net) · [Dataset links](docs/ORIGINAL_README.md) · [Apache-2.0](LICENSE)

## Getting started

Run commands from the repository root. The original implementation contains hard-coded `.cuda()` calls and currently requires an **NVIDIA CUDA environment**. Setting `num_gpu: 0` does not guarantee CPU or Mac inference.

Dependencies include Python, PyTorch, a matching torchvision version, NumPy, OpenCV, Pillow, PyYAML, tqdm, entmax, thop, and TensorBoard. Enable W&B logging only after installing its client. The historical repository does not pin versions; a complete dependency environment has not been installed or validated for this release.

1. Prepare data using the [original dataset instructions](docs/ORIGINAL_README.md). Pair each low-light input with a normally exposed ground-truth image using matching filenames.
2. Edit both dataset directories in `options/test/model/test.yml`. Relative paths resolve from the repository root; absolute paths are also supported.
3. Run in a CUDA environment:

```sh
python -m codes.test -opt options/test/model/test.yml
```

Results are saved to `results/FLGenNet_LOLv2/`. Each comparison contains the input, enhanced image, and ground truth, in that order. The default configuration uses paired LOLv2 test data. Do not use the input itself as ground truth to report enhancement metrics.

Training entry point:

```sh
python -m codes.train -opt options/train/model/FLGNet.yml
```

Update the training and validation directories first. Epoch/iteration counts, losses, and prefetch settings retain the original project configuration and have not been revalidated.

## Maintenance and validation

Maintenance fixes cover model/network class names in configuration, automatic discovery of `FLG.py`, a missing module import, portable path handling, and a duplicated checkpoint path prefix. Checkpoint loading requests `weights_only=True` when the installed PyTorch exposes that option, with compatibility for older signatures. **The neural architecture file `codes/models/archs/FLG.py` remains unchanged.** Existing Git history and the license are preserved.

```sh
python -m unittest discover -s tests -v
```

The dependency-free checks cover Python syntax, registry discovery, configuration class names, relative/absolute paths, and modern/legacy checkpoint-loader signatures using stubs. They do not require PyTorch or read the checkpoint. **Real training, inference, checkpoint compatibility, and PSNR/SSIM measurements have not been validated for this release**, so no new benchmark scores are claimed. Historical result images remain available as project materials.
